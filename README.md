# bibblebob

A digital business card and a business card organiser for Android. No accounts, no server, and the app has no internet permission.

- **My cards**: make any number of cards ("Work", "Freelance", …) and write any of them to an NFC tag, or copy its link.
- **Contacts**: tap someone's tag to save their card (it works offline), or scan a paper card with on-device text recognition. Everything is stored in SQLite on the phone.
- **Backup**: one file with every contact, every card and your settings.

Deployment, step by step: **[DEPLOY.md](DEPLOY.md)**.

## Repository layout

```
shared/   design.json   templates, palettes, fonts, link icons, limits, link dictionary
          icons.json    SVG icon paths
          LINK_FORMAT.md + link-vectors.json   the card-in-link format and its test vectors
site/     Cloudflare Pages (static): card page /c#<card>, vCard download, assetlinks.json
app/      Flutter Android app
brand/    logo sources (generated by tools/build-icons.mjs)
tools/    fetch-assets.mjs, sync-shared.mjs, test-linkcodec.mjs, build-icons.mjs
```

## How it fits together

- **The card is the link.** A card is packed into a compact binary format and placed after `#` in `https://bibblebob.pages.dev/c#…`; see [shared/LINK_FORMAT.md](shared/LINK_FORMAT.md). Browsers never send the part after `#` to a server, so the hosting service never sees whose card is opened.
- **Two codecs, one format.** The app (`app/lib/link/link_codec.dart`) and the website (`site/assets/linkcodec.js`) encode and decode the format. Both are tested against `shared/link-vectors.json`, so they can't drift apart.
- **Fitting stickers.** When writing a tag, the app reads its capacity and fills it in priority order: name, phone, email, business, title, links, description. A small NTAG213 still carries the essentials, and NTAG215/216 hold the full card. The editor shows what fits.
- **Cards are data, never images.** `app/lib/card/card_view.dart` and `site/assets/render.js` + `card.css` both draw cards from the same `shared/design.json`, with the same metrics, the same bundled Google Fonts and the same SVG icons. If you change a layout, change both.
- **Receiving.** Tags hold a single NDEF URL record and are never locked. Android App Links send `/c` links to the app when it's installed. The app decodes the card and saves it, no download involved. Each card carries a random 3-byte ID, so tapping the same person's tag again updates the contact instead of duplicating it. Without the app, the static page renders the card and offers a `.vcf` download.

## Adding things later

- **App theme**: add an entry to `app/assets/app_themes.json` (accent plus the text colour to use on it).
- **Card template / palette / font / link icon**: **append** it to its list in `shared/design.json` (never reorder: links on existing tags refer to positions), then run `node tools/sync-shared.mjs`. A new font also needs `node tools/fetch-assets.mjs` and a `fonts:` entry in `app/pubspec.yaml`. A new header or link style needs code in both renderers.
- **Changing the link format**: bump the version in both codecs, keep decoding v1, and regenerate the vectors with `node tools/test-linkcodec.mjs --write`.
